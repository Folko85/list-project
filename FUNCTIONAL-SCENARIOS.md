# Сценарии, которые должны продолжить работать

Этот список фиксирует минимально необходимое поведение приложения на каждом этапе перехода с Java Spring Boot на Dart и Flutter. После каждого этапа сценарии должны оставаться доступными и проверяемыми.

## Регистрация

- Новый пользователь может зарегистрироваться, указав имя пользователя, имя, фамилию и пароль.
- После успешной регистрации приложение подтверждает результат и позволяет перейти ко входу.
- Повторная регистрация уже занятого имени пользователя отклоняется с понятным сообщением.
- Некорректное имя пользователя или пустые обязательные поля не приводят к созданию аккаунта; пользователь видит причину отказа.

## Вход и выход

- Зарегистрированный пользователь может войти с корректными учетными данными.
- При успешном входе приложение сохраняет авторизацию и открывает список его задач.
- Неверные учетные данные приводят к понятному сообщению об ошибке; защищенные данные не показываются.
- После выхода защищенные разделы больше не доступны без повторного входа.

## Просмотр профиля

- Авторизованный пользователь может просмотреть профиль со своим именем пользователя, именем и фамилией.
- При отсутствии пользователя или авторизации приложение сообщает об ошибке и не показывает чужие данные.

## Просмотр списка задач

- Авторизованный пользователь видит список только своих задач.
- Для каждой задачи отображается ее название.
- Если задач нет, приложение показывает пустой список и позволяет создать первую задачу.
- Изменения в списке после операций создания, редактирования и удаления отражаются пользователю.

## Создание задачи

- Авторизованный пользователь может создать задачу с непустым названием.
- После успешного создания новая задача появляется в его списке.
- Пустое название не принимается; приложение сообщает, что нужно исправить.
- Созданная задача принадлежит текущему пользователю.

## Редактирование задачи

- Авторизованный пользователь может изменить название своей задачи.
- После успешного сохранения в списке отображается новое название.
- Пустое название не принимается.
- Редактирование не должно менять владельца задачи и не должно позволять изменять задачу другого пользователя.

## Удаление задачи

- Авторизованный пользователь может удалить отдельную свою задачу.
- После успешного удаления задача пропадает из списка.
- Удаление не должно затрагивать задачи других пользователей.

## Удаление всех задач

- Авторизованный пользователь может удалить все свои задачи.
- После операции в его списке не остается задач.
- Операция не должна затрагивать задачи других пользователей.

## Сквозные критерии

- Перезагрузка приложения не сбрасывает список задач или авторизацию активного пользователя неожиданным образом.
- Ошибки регистрации, входа и работы с задачами видны пользователю; приложение не сообщает об успехе, если операция не выполнена.
- Данные одного пользователя изолированы от данных остальных пользователей для просмотра, создания, редактирования и удаления.
